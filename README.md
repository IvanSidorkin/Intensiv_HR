# Employee Churn Classification (Прогнозирование оттока сотрудников)

Проект по разработке модели машинного обучения для бинарной классификации оттока персонала (уволится сотрудник или нет). Задача решалась в рамках учебного интенсива с валидацией решений на платформе **Codabench** (итоговый результат **ROC-AUC: 0.93**).

## 📌 Ключевые этапы проекта

### 1. Предобработка данных и Data Pipeline
* **Сборка датасета:** Реализован пайплайн автоматического рекурсивного поиска и объединения фрагментированных данных из папок (форматы `.csv` и `.parquet`) с контролем эталонного порядка колонок.
* **Очистка дубликатов:** Обнаружены и агрегированы скрытые дубликаты по уникальному идентификатору (столбец `Телефон`), что позволило восстановить пропуски и сократить объем "грязных" данных более чем в 2 раза.
* **Фильтрация:** Удалены информационно-пустые строки (содержащие 6 и более пропусков `NaN`).

### 2. Разведочный анализ (EDA) и Feature Selection
* **Анализ утечек (Data Leakage):** Выявлена критическая взаимосвязь (в 94% случаев) между признаком `Подписаны_документы` и целевой переменной. Признак удален, так как он отсутствовал в тестовом наборе Codabench и приводил к переобучению.
* **Статистические тесты:** Проведен тест $\chi^2$ (Хи-квадрат) для категориальных признаков. Исключен нерелевантный признак `Знак_зодиака`.
* **Корреляционный анализ:** Найдена мультиколлинеарность между `Возраст` и `Год_рождения` (последний удален).
* **Обработка пропусков:** Категориальные признаки заполнены модой, числовые — средним значением (выбросов в данных не обнаружено).
* **Баланс классов:** Выборка сбалансирована в пропорции 60/40 (сохранение/увольнение).

### 3. Моделирование и подбор гиперпараметров
В качестве базового алгоритма выбран **CatBoost Classifier**, так как он эффективно работает с категориальными признаками из "коробки" без ручного кодирования.

* Разделение выборки: Стратифицированное разбиение (Stratified Train/Test) в пропорции 80/20.
* Автоматический подбор параметров проводился с помощью встроенного метода `grid_search()`.
* Финальные оптимальные параметры модели:
  * `iterations`: 400
  * `depth`: 7
  * `learning_rate`: 0.2
  * `l2_leaf_reg`: 10 (регуляризация подобрана вручную для борьбы с оверфиттингом)

## 📊 Результаты и метрики (ROC-AUC)

| Выборка | ROC-AUC |
| :--- | :---: |
| **Обучающая (Train)** | 0.97 |
| **Тестовая (Test)** | 0.85 |
| **Платформа Codabench** | **0.93** |

*Разница в метриках между локальным тестом и платформой обусловлена малым размером локальной тестовой выборки, однако высокий результат на скрытых данных Codabench подтверждает отличную обобщающую способность модели.*
